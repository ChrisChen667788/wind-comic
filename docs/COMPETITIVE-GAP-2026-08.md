**但护城河边界仍然成立** —— 逐项核对后,**无一同时具备「情绪节奏审计 + EDL/AAF 剪辑线导出 + 开源自托管商用」**:

- **OpenMontage**(最接近):AGPL 自托管 ✓、TTS 多 provider ✓、多语发行 ✓、预算阈值审批 ✓ ——
  但它的「节奏审计」是 **anti-slideshow 静态检测**(判画面是否太像幻灯片),不是情绪节奏/反转/cliffhanger 审计;
  **无 EDL/AAF**;「协作」是生产状态看板,不是 Yjs 多用户联合编辑;无 BYO 注册表(用评分选择层)。

- **BigBanana**:CC BY-NC-SA **禁商用**。
- **ViMax**:MIT ✓,但无 TTS/配音、无节奏审计、无 EDL/AAF、无协作、无发布预检、无 BYO 注册表。

> **结论(可证伪)**:截至 2026-08-31,**开源侧仍无人同时具备这三项**。
> 但 OpenMontage 已经补上了 TTS 与多语 —— **边界在收窄,不是在扩大**。

- **Seedance 2.5**(7-31)与 **Wan 3.0**(8-24 正式上线)双双做到**原生 30s 单镜头**;
  Seedance 支持 **50 个参考素材**(按 token 计费 ¥42–70/百万);Wan 3.0 720P 折后 **¥0.42/s**,还能**文档直转视频**。
- **Vidu Q3** 是国产里唯一明确打「短剧/漫剧工业化」的:7 参考图多主体锁定 + 6 类电影特效 + 口型驱动(Turbo 1080p ≈¥0.41/s)。
- **PixVerse C1**(4-08):短剧垂直定位最明确,分镜宫格直出 + 多人对白口型。
- **Kling 3.0 Turbo / Omni**(6-17):¥0.8/s 起(720P 含音频),extension 最长约 3 分钟。

> **两条自查结论(比竞品本身更要紧)**
> ① **我们默认在用的 `MiniMax-Hailuo-2.3` / `2.3-Fast` 已被官方降为 legacy**,H3(V2)才是官方推荐路径;
> ② **两条 Vidu 路径版本不一致**:一条钉 `viduq3`,另一条**一个模型字段都不传**、跑供应商默认值 —— 和 MJ 未钉版本是同一个病。
> 这两条都属于「已经接了但版本落后」,修复成本低、收益直接。

### ④ Agent 工程出现两个值得直接借鉴的范式

- **Anthropic Outcomes**:用**独立 grader agent** 评估主 agent 输出,避免自我合理化,实测成功率 +8–10pp。
  Wind Comic 的 Vision Audit 目前是**同一个 agent 既生成又打分**,存在同样的自我合理化风险。
- **Devin 的 ACU 预算上限 + 里程碑 checkpoint**:超限**暂停待人工 review**,而不是硬失败。
  Wind Comic 有引擎配额判定,但**没有 token 预算硬限制** —— 一次长剧本生成可能超出预期成本。

## 3. 优势 / 劣势(对着上表结论,不空谈)

### 我们真正的优势(竞品逐项核对后确实没有的)

1. **情绪节奏 / 反转 / cliffhanger 审计** —— 开源侧无人有;OpenMontage 那套是画面静态检测,性质不同。
2. **EDL / AAF / 剪映导出** —— 全部已查竞品(开源与商业)中**无人提供**。这是「AI 出片」与「进专业后期」之间的桥。
3. **Yjs 实时协作 + 三档权限** —— OpenMontage 只有状态看板,ViMax/BigBanana/DramaClaw 全无。
4. **BYO provider 注册表** —— 竞品越强本管线越强;而竞品多是「绑定自家或固定几家」。
5. **发布预检**(抖音/小红书/视频号安全区与时长)—— 未见竞品有。
6. **工程可信度** —— 5187 单测、六道入库门禁、双驱动。这在开源同类里是显著异常值。

### 我们真正的劣势(不粉饰)

1. **生成质量不由我们决定** —— 我们不训模型,上限即所接引擎的上限。榜首换人时我们只能跟着换 key。
2. **零门槛比不过** —— Coze 3.0「内容创作技能包」、国内一键成片平台,新手 5 分钟出片;
   Wind Comic 要装、要配 key、要理解流水线。市场 YoY +214%,这一差距会被快速放大。
3. **参考图路数落后** —— Grok 7 路 vs 我们 2 路(cref+sref)。
4. **无作曲能力**(MiniMax Music 已停用),而竞品普遍自带 BGM。
5. **特色能力普遍没用满** —— 见上表第三列:Veo 的 Scene Extension、Kling 的多镜连贯与自带口型、
   Kontext 的局部重绘,都是**已接入但没调用**。这是当前**性价比最高的一块**:不需要新供应商,只要把已有的用起来。
6. **无多平台自动分发** —— Manus 那类能「1 内容 → 50+ 平台」,我们只做到发布预检。

## 4. 迭代方案(融入 v12.402+,已同步进 `ROADMAP-v12.171+.md` Batch K)

> 排序依据:**先修可能已经坏掉的 → 再把已接入的用满 → 再补真实缺口 → 最后才是新供应商**。

### P0 · 已经落后或可能已失效的(最高优先)

- **P0-1 MiniMax 模型升版(v12.402)**:默认 `MiniMax-Hailuo-2.3` **已被官方标为 legacy**,
  官方推荐路径是 **H3(V2 API)**。继续用 legacy 模型 = 随时可能像 Music API 那样被停掉
  (那次的教训犹在:410 + 2153,毫无预告)。H3 还自带**免费音频输入 + 口型自动对齐**。
- **P0-2 Vidu 钉版本(v12.403)**:两条路径一条钉 `viduq3`、一条**不传 model** 跑供应商默认;钉住 Q3 才谈得上用上它的短剧特效包 + 7 参考图多主体锁定,
  而 Vidu Q3 恰恰是国产里唯一明确打短剧工业化的 —— **既是竞品也是最佳引擎候选**。

- **P0-3 `--cref` → `--oref`(v12.404)**
  `midjourney.service.ts:81` 仍在拼 `--cref`,而代码**未指定 MJ 版本**、走网关默认。
  若网关已升 V7,`--cref` 失效 → **角色锁脸在 MJ 路径上静默失效**,而 cameo-vision-retry 会因此频繁触发重生、白烧额度。
  ⚠️ **需实测确认**(本轮无 MJ 额度可验)。做法:显式声明版本 + 按版本切参数,并加「锁脸生效」的可观测指标
  (vision retry 触发率突增即报警)。

### P1 · 把已接入的用满(不需要新供应商,性价比最高)

- **P1-1 Kling 多镜连贯(v12.405–406)**:一次调用出 6 个连贯镜头,替代现在「逐镜生成 + 靠 DNA 拼一致性」。
- **P1-2 Veo Scene Extension(v12.407)**:把成片接到 60s+ —— 注意**这是拼接,单次生成上限仍是 8–10s**;缓解短剧「镜头太碎」。
- **P1-3 Kontext 指令式局部重绘(v12.408)**:分镜审计 <70 分时,**只重绘出问题的区域**,而不是整张重生 —— 省钱且更稳。
- **P1-4 Kling 自带多语对白+口型(v12.409)**:与自研 TTS 链做 A/B,择优或按语种分流。

### P2 · 补真实缺口

- **P2-1 音乐能力(v12.410–411)**:接 **ElevenLabs Music v2**($0.15/min,授权语料、商用最干净,
  与未来 TTS 同厂同 key)为主;同时把 **YuE / ACE-Step 1.5**(Apache-2.0)注册为自托管备选 ——
  符合本项目「开源自托管」的定位,也不受单一供应商停服影响(MiniMax Music 的教训)。
- **P2-2 独立 grader(v12.412)**:把 Vision Audit 从「自评」改成**独立评分 agent**(借鉴 Anthropic Outcomes)。
- **P2-3 token 预算上限(v12.413)**:借鉴 Devin ACU —— 每个 Agent 任务注入预算,**超限暂停待确认**而非硬失败。

### P3 · 新供应商 / 新能力

- **P3-1 Grok Imagine(v12.414)**:7 路视觉参考,注册进 provider 注册表(BYO 架构下成本很低)。
- **P3-2 Seedream 4.5(v12.415)**:中文文字渲染领先,可用于**片头/字卡**这类必须画中文的场景。
- **P3-3 ElevenLabs v3 audio tags(v12.416)**:与现有「情绪→韵律」模块对接,情绪标签直接注入 audio tag。
- **P3-4 降低上手门槛(v12.417+)**:这是最大的战略劣势。方向:一键 demo 工程 / 预置模板 / Docker 一行起。

## 5. 本轮明确**不做**的
